Introducción a los Procedimientos Almacenados

Un procedimiento almacenado (Stored Procedure) es un conjunto de instrucciones SQL que se almacenan y compilan en el servidor de la base de datos. Puede ejecutarse tantas veces como sea necesario, lo que lo convierte en una herramienta fundamental para encapsular lógica y optimizar el trabajo con datos.

Ventajas principales

  • Reutilización: un mismo procedimiento puede invocarse desde múltiples aplicaciones o scripts.
  • Rendimiento: el código se compila una sola vez; las ejecuciones posteriores son más rápidas.
  • Seguridad: es posible otorgar permiso para ejecutar un SP sin dar acceso directo a las tablas.
  • Mantenimiento: los cambios se aplican en un único lugar, simplificando las actualizaciones.
  • Reducción de tráfico: se envía una sola llamada en lugar de múltiples consultas.
Recomendación inicial: comenzar con SPs que realicen una sola operación (INSERT, UPDATE o SELECT). Una vez dominados, combinar varias operaciones dentro del mismo procedimiento.

Sintaxis básica

La estructura fundamental para crear un procedimiento almacenado en MySQL es:

DELIMITER // CREATE PROCEDURE nombre_procedimiento ( parámetros ) BEGIN -- Sentencias SQL aquí END // DELIMITER ;

Elementos clave

  • DELIMITER: MySQL usa ; como delimitador por defecto. Al cambiarlo temporalmente (ej. a //), se evita que MySQL interprete mal los puntos y coma dentro del SP.
  • CREATE PROCEDURE: define el nombre del procedimiento.
  • BEGIN … END: bloque que contiene el código del procedimiento.
  • Al final, se restaura el delimitador con DELIMITER ;.

Ejemplo básico

Supóngase una tabla clientes con id_cliente, nombre y saldo.

DELIMITER // CREATE PROCEDURE actualizar_saldo ( IN p_id_cliente INT, IN p_nuevo_saldo DECIMAL(10,2) ) BEGIN UPDATE clientes SET saldo = p_nuevo_saldo WHERE id_cliente = p_id_cliente; END // DELIMITER ;

Ejecutar un SP

CALL actualizar_saldo(1, 500.00);

Eliminar un SP

DROP PROCEDURE IF EXISTS actualizar_saldo;
Nota: en MySQL Workbench o cualquier cliente, si se modifica un SP, es recomendable eliminarlo y volverlo a crear. Esta práctica ayuda a evitar errores de sintaxis y a internalizar la estructura completa.

Parámetros en Procedimientos Almacenados

MySQL permite tres tipos de parámetros para los SP:

Tipo Descripción Ejemplo
IN Parámetro de entrada. El procedimiento recibe un valor. IN p_id INT
OUT Parámetro de salida. El procedimiento devuelve un valor. OUT p_saldo DECIMAL(10,2)
INOUT Entrada y salida. Se recibe un valor y se devuelve modificado. INOUT p_contador INT

Ejemplo con OUT

Procedimiento que devuelve el saldo de un cliente:

DELIMITER // CREATE PROCEDURE obtener_saldo ( IN p_id_cliente INT, OUT p_saldo DECIMAL(10,2) ) BEGIN SELECT saldo INTO p_saldo FROM clientes WHERE id_cliente = p_id_cliente; END // DELIMITER ;

Ejecutar con OUT

-- Variable de usuario para recibir el valor SET @saldo_cliente = 0; -- Llamada al procedimiento CALL obtener_saldo(1, @saldo_cliente); -- Ver el resultado SELECT @saldo_cliente AS 'Saldo actual';
Observación: las variables de usuario se identifican con el prefijo @ y persisten durante toda la sesión. Son ideales para recibir valores de parámetros OUT.

Variables en Procedimientos Almacenados

Dentro de un SP es posible declarar y usar distintos tipos de variables:

Tipo Ámbito Ejemplo
DECLARE Local al bloque BEGIN…END DECLARE total INT;
SET (asignación) Local o de usuario SET total = 100;
@variable Global a la sesión SET @contador = 0;
SELECT … INTO Asigna resultado de consulta a variable local SELECT COUNT(*) INTO total FROM clientes;

Ejemplo completo

DELIMITER // CREATE PROCEDURE ejemplo_variables ( IN p_id INT, OUT p_resultado DECIMAL(10,2) ) BEGIN -- Declaración de variables locales DECLARE v_nombre VARCHAR(100); DECLARE v_saldo DECIMAL(10,2); DECLARE v_total_clientes INT; -- Asignar valores desde la tabla SELECT nombre, saldo INTO v_nombre, v_saldo FROM clientes WHERE id_cliente = p_id; SELECT COUNT(*) INTO v_total_clientes FROM clientes; -- Asignación con SET SET p_resultado = v_saldo + 100; -- Variable de usuario (persiste fuera del SP) SET @ultimo_cliente = v_nombre; END // DELIMITER ;
Nota: las variables declaradas con DECLARE solo existen dentro del SP. Las variables de usuario (@variable) pueden usarse incluso después de que el SP finalice.

Estructuras de control

Los SP soportan lógica condicional e iterativa, lo que los convierte en verdaderos programas dentro de la base de datos.

IF … THEN … ELSE

IF condicion THEN -- código si es verdadero ELSEIF otra_condicion THEN -- código para otra condición ELSE -- código si ninguna se cumple END IF;

CASE

CASE valor WHEN 1 THEN -- acción 1 WHEN 2 THEN -- acción 2 ELSE -- acción por defecto END CASE;

WHILE (bucle)

WHILE condicion DO -- código a repetir END WHILE;

LOOP con LEAVE (salida)

nombre_bucle: LOOP -- código IF condicion_salida THEN LEAVE nombre_bucle; END IF; END LOOP;
Ejemplo: clasificar clientes por saldo
DELIMITER // CREATE PROCEDURE clasificar_cliente ( IN p_id INT, OUT p_categoria VARCHAR(20) ) BEGIN DECLARE v_saldo DECIMAL(10,2); SELECT saldo INTO v_saldo FROM clientes WHERE id_cliente = p_id; IF v_saldo >= 1000 THEN SET p_categoria = 'Premium'; ELSEIF v_saldo >= 500 THEN SET p_categoria = 'Estándar'; ELSE SET p_categoria = 'Básico'; END IF; END // DELIMITER ;

Funciones nativas útiles

MySQL ofrece muchas funciones que pueden usarse dentro de los SP para agilizar tareas comunes.

Función Descripción Ejemplo
LAST_INSERT_ID() ID de la última fila insertada con AUTO_INCREMENT SET @id = LAST_INSERT_ID();
ROW_COUNT() Número de filas afectadas por la última operación IF ROW_COUNT() = 0 THEN ...
CURDATE() Fecha actual (YYYY-MM-DD) INSERT INTO log (fecha) VALUES (CURDATE());
NOW() Fecha y hora actual SELECT NOW();
IFNULL(expr, valor) Devuelve valor si expr es NULL SELECT IFNULL(saldo, 0) FROM clientes;
CONCAT(str1, str2, ...) Concatena cadenas de texto SET @mensaje = CONCAT('Hola ', nombre);
DATE_ADD(fecha, INTERVAL) Suma un intervalo a una fecha DATE_ADD(CURDATE(), INTERVAL 7 DAY)
DATE_SUB(fecha, INTERVAL) Resta un intervalo a una fecha DATE_SUB(CURDATE(), INTERVAL 1 MONTH)
IF(cond, verdadero, falso) Condicional en línea SELECT IF(saldo > 0, 'Activo', 'Inactivo');

Ejemplo combinado

DELIMITER // CREATE PROCEDURE registrar_compra ( IN p_cliente_id INT, IN p_monto DECIMAL(10,2) ) BEGIN DECLARE v_nuevo_id INT; -- Insertar compra INSERT INTO compras (id_cliente, fecha, monto) VALUES (p_cliente_id, CURDATE(), p_monto); -- Obtener el ID generado SET v_nuevo_id = LAST_INSERT_ID(); -- Actualizar saldo del cliente UPDATE clientes SET saldo = saldo - p_monto WHERE id_cliente = p_cliente_id; -- Mostrar mensaje con CONCAT SELECT CONCAT('Compra registrada. ID: ', v_nuevo_id) AS Mensaje; END // DELIMITER ;

Subconsultas dentro de SP

Las subconsultas son consultas anidadas dentro de otra consulta. Son muy útiles dentro de los SP para tomar decisiones o filtrar datos de manera dinámica.

Ejemplo: productos con precio mayor al promedio de su categoría

DELIMITER // CREATE PROCEDURE productos_mas_caros_por_categoria() BEGIN SELECT p.nombre, p.precio, p.categoria FROM productos p WHERE p.precio > ( SELECT AVG(precio) FROM productos WHERE categoria = p.categoria ); END // DELIMITER ;

Ejemplo con EXISTS

Clientes que han comprado más de 3 productos de una categoría específica:

DELIMITER // CREATE PROCEDURE clientes_con_compras_categoria ( IN p_categoria VARCHAR(50) ) BEGIN SELECT c.nombre, c.apellido FROM clientes c WHERE EXISTS ( SELECT 1 FROM pedidos p INNER JOIN detalles_pedido dp ON p.id = dp.pedido_id INNER JOIN productos pr ON dp.producto_id = pr.id WHERE p.cliente_id = c.id AND pr.categoria = p_categoria GROUP BY p.cliente_id HAVING SUM(dp.cantidad) > 3 ); END // DELIMITER ;
Observación: EXISTS es una función booleana que devuelve TRUE si la subconsulta devuelve al menos una fila. Resulta eficiente para validar condiciones.

Buenas prácticas

  • Nombrar los parámetros con prefijo: usar p_ para parámetros (ej. p_id_cliente) y v_ para variables locales. Esto evita confusiones con nombres de columnas.
  • Probar cada SP por separado: ejecutar el SP con diferentes valores para verificar su correcto funcionamiento.
  • Agregar comentarios: explicar qué hace cada sección del código facilita el mantenimiento.
  • Eliminar y volver a crear: durante el aprendizaje, es preferible borrar el SP y reescribirlo desde cero en lugar de modificarlo con ALTER. Esto refuerza el conocimiento de la sintaxis.
  • Empezar por lo simple: primero desarrollar SP que realicen una sola operación (INSERT, UPDATE, SELECT). Luego combinar operaciones.
  • Utilizar ROW_COUNT() para validar si una operación afectó filas (ej. al actualizar o eliminar).
  • Aprovechar CURDATE() y NOW() para registrar fechas automáticamente.
Resumen del flujo de trabajo
  1. Diseñar qué debe hacer el SP (entrada, proceso, salida).
  2. Escribir el SP con DELIMITER, CREATE PROCEDURE y BEGIN … END.
  3. Probar con CALL usando valores de prueba.
  4. Verificar los resultados (consultar tablas, variables de salida).
  5. Corregir errores y repetir hasta que funcione correctamente.
Nota: en MySQL Workbench, si se cambia el delimitador, debe restaurarse a ; al final; de lo contrario, los comandos posteriores pueden fallar.
