Subconsultas SQL: guía autodidacta paso a paso

Material teórico para aprender subconsultas de manera progresiva. La idea es partir de consultas conocidas, como SELECT, WHERE, JOIN, GROUP BY y HAVING, y avanzar hacia consultas que dependen del resultado de otras consultas.

Objetivo del apunte

Al finalizar este material deberías poder leer, interpretar y escribir subconsultas sencillas y medianamente complejas, entendiendo cuándo una subconsulta devuelve un valor, una lista o una tabla, y qué operador conviene usar en cada caso.

1. Punto de partida: qué ya deberíamos saber

Antes de estudiar subconsultas, conviene tener claros estos temas:

  • SELECT: permite seleccionar columnas.
  • FROM: indica de qué tabla se obtienen los datos.
  • WHERE: filtra filas antes de agrupar.
  • JOIN: permite combinar datos de varias tablas relacionadas.
  • GROUP BY: agrupa filas para aplicar funciones como COUNT, SUM, AVG, MIN y MAX.
  • HAVING: filtra grupos luego de aplicar GROUP BY.
Idea central

Una subconsulta aparece cuando para resolver una pregunta necesito responder primero otra pregunta más pequeña.

3. Qué es una subconsulta

Una subconsulta es una consulta SELECT escrita dentro de otra consulta. También puede llamarse consulta anidada o subquery.

SELECT columnas
FROM tabla
WHERE columna operador (
    SELECT columna_o_calculo
    FROM otra_tabla
    WHERE condicion
);

En esa estructura hay dos partes:

  • Consulta externa: es la consulta principal, la que finalmente devuelve el resultado.
  • Consulta interna: es la subconsulta, ubicada entre paréntesis.
Regla básica

Las subconsultas se escriben entre paréntesis. Esto ayuda a que SQL sepa qué parte debe resolver primero y cómo usar ese resultado dentro de la consulta principal.

4. Por qué usar subconsultas

Las subconsultas son útiles cuando una consulta depende del resultado de otra. En lugar de resolver un problema en varios pasos separados, podemos escribir una sola instrucción SQL.

4.1 Ejemplo sencillo: productos más caros que el promedio

Supongamos que queremos listar los productos cuyo precio sea mayor al precio promedio general.

Paso 1: primero necesito saber cuál es el precio promedio. 
SELECT AVG(precio)
FROM productos;
Paso 2: después necesito buscar productos cuyo precio sea mayor que ese promedio. 
SELECT nombre, precio
FROM productos
WHERE precio > 66000;

El problema es que escribir 66000 manualmente no es conveniente. Si cambian los precios o se agregan productos, el promedio cambia.

Consulta final con subconsulta: dejamos que SQL calcule el promedio y lo use directamente. 
SELECT nombre, precio
FROM productos
WHERE precio > (
    SELECT AVG(precio)
    FROM productos
);
Lectura en castellano

Mostrar los productos cuyo precio sea mayor que el promedio de precio de todos los productos.

4.2 Algo que no se resuelve cómodamente con una consulta simple

Ahora pensemos esta pregunta:

¿Qué clientes nunca realizaron una compra?

Con una consulta simple sobre clientes no alcanza, porque la información de las compras está en otra tabla: ventas. Necesitamos comparar clientes contra ventas y detectar ausencia de registros.

SELECT c.nombre
FROM clientes AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM ventas AS v
    WHERE v.id_cliente = c.id_cliente
);

Esta consulta dice: mostrar cada cliente para el cual no exista ninguna venta asociada.

Por qué este caso es importante

Las subconsultas no sirven solo para calcular números. También sirven para responder preguntas de existencia: quién tiene registros relacionados y quién no los tiene.

5. Tipos de subconsultas según el resultado que devuelven

Para elegir correctamente el operador, primero hay que mirar qué devuelve la subconsulta.

TipoQué devuelveEjemplo de resultadoOperadores habituales
EscalarUna sola fila y una sola columna.66000=, >, <, >=, <=, <>
ListaUna columna y varias filas.1, 2, 4IN, NOT IN, ANY, SOME, ALL
Tabla derivadaVarias filas y varias columnas.Una tabla temporal de resultados.Se usa en FROM con alias.

Clave para evitar errores

Si la subconsulta devuelve varios valores, no puedo compararla con = como si fuera un solo valor. Para listas debo usar operadores pensados para listas, como IN, ANY o ALL.

6. Subconsultas escalares

Una subconsulta escalar devuelve un único valor. Por eso puede usarse como si fuera un número, texto o fecha.

6.1 Productos con el precio máximo

Primero obtengo el precio máximo:

SELECT MAX(precio)
FROM productos;

Luego uso ese valor para buscar el producto correspondiente:

SELECT nombre, precio
FROM productos
WHERE precio = (
    SELECT MAX(precio)
    FROM productos
);

Esta consulta puede devolver más de un producto si hay empate en el precio máximo. Eso no está mal: la subconsulta devuelve un solo valor, pero varias filas de la consulta externa pueden coincidir con ese valor.

6.2 Clientes mayores que el promedio de edad

SELECT nombre, edad
FROM clientes
WHERE edad > (
    SELECT AVG(edad)
    FROM clientes
);

La subconsulta calcula un valor: el promedio de edad. La consulta externa compara la edad de cada cliente contra ese valor.

6.3 Subconsulta escalar en SELECT

También podemos mostrar un dato calculado por subconsulta como una columna más.

SELECT nombre,
       precio,
       (SELECT AVG(precio) FROM productos) AS promedio_general
FROM productos;

En este caso, cada fila muestra el producto, su precio y el promedio general de todos los productos.

Cuidado

Cuando una subconsulta está en el SELECT como columna, normalmente debe devolver un único valor. Si devuelve varias filas, SQL no sabrá qué valor mostrar en esa celda.

7. Subconsultas que devuelven listas

Una subconsulta de lista devuelve una sola columna, pero puede devolver varias filas. Es útil cuando quiero comparar un valor contra un conjunto de valores.

7.1 Clientes que realizaron compras

Primero puedo obtener los identificadores de clientes que aparecen en ventas:

SELECT id_cliente
FROM ventas;

Luego uso esa lista para filtrar clientes:

SELECT nombre
FROM clientes
WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
);

Lectura: mostrar los clientes cuyo id_cliente esté dentro de la lista de clientes que realizaron ventas.

7.2 Productos vendidos al menos una vez

SELECT nombre
FROM productos
WHERE id_producto IN (
    SELECT id_producto
    FROM detalle_ventas
);

La subconsulta devuelve una lista de productos que aparecen en el detalle de ventas. La consulta externa muestra sus nombres desde la tabla productos.

8. Operadores IN y NOT IN

IN pregunta si un valor pertenece a una lista. NOT IN pregunta si un valor no pertenece a una lista.

8.1 IN con una lista escrita manualmente

SELECT nombre, ciudad
FROM clientes
WHERE ciudad IN ('Mar del Plata', 'Balcarce');

Esto equivale a escribir:

SELECT nombre, ciudad
FROM clientes
WHERE ciudad = 'Mar del Plata'
   OR ciudad = 'Balcarce';

8.2 IN con subconsulta

SELECT nombre
FROM clientes
WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
);

Acá la lista no la escribimos nosotros. La genera una subconsulta.

8.3 NOT IN

SELECT nombre
FROM productos
WHERE id_producto NOT IN (
    SELECT id_producto
    FROM detalle_ventas
);

Lectura: mostrar productos cuyo identificador no aparezca en el detalle de ventas.

Advertencia importante sobre NOT IN y NULL

Si la subconsulta usada con NOT IN devuelve algún valor NULL, el resultado puede ser inesperado o incluso no devolver filas. Por eso, cuando se busca ausencia de registros relacionados, muchas veces es más seguro usar NOT EXISTS.

9. Operadores ANY, SOME y ALL

Estos operadores permiten comparar un valor contra una lista usando operadores como >, <, =, <>, etc.

9.1 ANY y SOME

ANY significa “alguno”. SOME es sinónimo de ANY en SQL.

SELECT nombre, precio
FROM productos
WHERE precio > ANY (
    SELECT precio
    FROM productos
    WHERE categoria = 'Libreria'
);

Lectura: mostrar productos cuyo precio sea mayor que al menos uno de los precios de la categoría Libreria.

Si uso > ANY, alcanza con superar al menor valor de la lista. Si un producto es mayor que alguno, ya cumple.

9.2 ALL

ALL significa “todos”. La condición debe cumplirse contra todos los valores devueltos por la subconsulta.

SELECT nombre, precio
FROM productos
WHERE precio > ALL (
    SELECT precio
    FROM productos
    WHERE categoria = 'Libreria'
);

Lectura: mostrar productos cuyo precio sea mayor que todos los precios de la categoría Libreria.

Si uso > ALL, debo superar al mayor valor de la lista. Es una condición más exigente que > ANY.

9.3 Comparación mental rápida

CondiciónSe cumple si...Equivalencia aproximada
> ANY (lista)Es mayor que algún valor de la lista.Mayor que el mínimo.
> ALL (lista)Es mayor que todos los valores de la lista.Mayor que el máximo.
< ANY (lista)Es menor que algún valor de la lista.Menor que el máximo.
< ALL (lista)Es menor que todos los valores de la lista.Menor que el mínimo.

10. EXISTS y NOT EXISTS

EXISTS no compara un valor contra una lista. Lo que hace es preguntar si la subconsulta devuelve al menos una fila.

10.1 Clientes que realizaron alguna compra

SELECT c.nombre
FROM clientes AS c
WHERE EXISTS (
    SELECT 1
    FROM ventas AS v
    WHERE v.id_cliente = c.id_cliente
);

Lectura: mostrar clientes para los cuales exista al menos una venta asociada.

¿Por qué SELECT 1?

Con EXISTS no importa qué columnas devuelve la subconsulta. Solo importa si devuelve filas. Por eso se suele escribir SELECT 1, aunque también podría verse SELECT *.

10.2 Clientes que nunca compraron

SELECT c.nombre
FROM clientes AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM ventas AS v
    WHERE v.id_cliente = c.id_cliente
);

Lectura: mostrar clientes para los cuales no exista ninguna venta asociada.

10.3 Productos nunca vendidos

SELECT p.nombre
FROM productos AS p
WHERE NOT EXISTS (
    SELECT 1
    FROM detalle_ventas AS dv
    WHERE dv.id_producto = p.id_producto
);
Cuándo preferir EXISTS

EXISTS suele ser muy claro cuando la pregunta es “existe o no existe un registro relacionado”. Además, evita algunos problemas típicos de NOT IN cuando hay valores NULL.

11. Subconsultas correlacionadas

Una subconsulta correlacionada es una subconsulta que depende de la consulta externa. Es decir: dentro de la subconsulta se usa una columna de la consulta principal.

SELECT c.nombre
FROM clientes AS c
WHERE EXISTS (
    SELECT 1
    FROM ventas AS v
    WHERE v.id_cliente = c.id_cliente
);

La subconsulta usa c.id_cliente, que pertenece a la consulta externa. Por eso no puede entenderse completamente sola: necesita saber qué cliente se está evaluando en ese momento.

Dicho simple

SQL toma un cliente de la consulta externa y pregunta: “¿Existe alguna venta para este cliente?”. Luego toma el siguiente cliente y repite la pregunta.

11.1 Producto más caro que el promedio de su propia categoría

Esta consulta es muy importante porque muestra una necesidad real de correlación.

SELECT p1.nombre, p1.categoria, p1.precio
FROM productos AS p1
WHERE p1.precio > (
    SELECT AVG(p2.precio)
    FROM productos AS p2
    WHERE p2.categoria = p1.categoria
);

Lectura: mostrar productos cuyo precio sea mayor que el promedio de precio de los productos de su misma categoría.

¿Por qué no alcanza con un promedio general?

Porque no estamos comparando contra el promedio de todos los productos. Estamos comparando cada producto contra el promedio de su propia categoría. La subconsulta necesita saber la categoría del producto que se está evaluando afuera.

11.2 Total gastado por cliente usando subconsulta correlacionada

SELECT c.nombre,
       (
           SELECT SUM(dv.cantidad * dv.precio_unitario)
           FROM ventas AS v
           JOIN detalle_ventas AS dv ON dv.id_venta = v.id_venta
           WHERE v.id_cliente = c.id_cliente
       ) AS total_gastado
FROM clientes AS c;

Para cada cliente, la subconsulta calcula el total gastado por ese cliente.

Atención al rendimiento

Las subconsultas correlacionadas pueden ser muy claras, pero en tablas grandes podrían ser más costosas. En muchos casos, una solución con JOIN y GROUP BY puede ser más eficiente. Lo importante al aprender es entender primero la lógica.

12. Subconsultas en SELECT, FROM y HAVING

12.1 Subconsulta en SELECT

Sirve para mostrar un cálculo como una columna adicional.

SELECT c.nombre,
       (
           SELECT COUNT(*)
           FROM ventas AS v
           WHERE v.id_cliente = c.id_cliente
       ) AS cantidad_ventas
FROM clientes AS c;

Por cada cliente se muestra cuántas ventas tiene asociadas.

12.2 Subconsulta en FROM: tabla derivada

Una subconsulta en FROM funciona como una tabla temporal generada en el momento. Es obligatorio darle un alias.

SELECT resumen.id_cliente,
       resumen.total_gastado
FROM (
    SELECT v.id_cliente,
           SUM(dv.cantidad * dv.precio_unitario) AS total_gastado
    FROM ventas AS v
    JOIN detalle_ventas AS dv ON dv.id_venta = v.id_venta
    GROUP BY v.id_cliente
) AS resumen
WHERE resumen.total_gastado > 50000;

La subconsulta crea una tabla derivada llamada resumen. La consulta externa filtra los clientes cuyo total gastado supera 50000.

Alias obligatorio

Cuando una subconsulta se usa en el FROM, debe tener un alias. Si no se escribe AS resumen u otro nombre, muchos motores SQL marcarán error.

12.3 Subconsulta en HAVING

HAVING filtra grupos. Podemos usar una subconsulta para comparar un resultado agrupado contra un valor calculado.

SELECT v.id_cliente,
       SUM(dv.cantidad * dv.precio_unitario) AS total_gastado
FROM ventas AS v
JOIN detalle_ventas AS dv ON dv.id_venta = v.id_venta
GROUP BY v.id_cliente
HAVING SUM(dv.cantidad * dv.precio_unitario) > (
    SELECT AVG(total_por_cliente)
    FROM (
        SELECT v2.id_cliente,
               SUM(dv2.cantidad * dv2.precio_unitario) AS total_por_cliente
        FROM ventas AS v2
        JOIN detalle_ventas AS dv2 ON dv2.id_venta = v2.id_venta
        GROUP BY v2.id_cliente
    ) AS totales
);

Lectura: mostrar clientes cuyo total gastado sea mayor que el promedio de gasto de los clientes que compraron.

Este ejemplo es más avanzado. Lo importante es reconocer que la subconsulta interna calcula una tabla de totales por cliente y luego la consulta externa compara contra el promedio de esos totales.

13. Subconsultas, JOIN, GROUP BY y HAVING

No todo problema que se resuelve con subconsulta debe resolverse necesariamente con subconsulta. Muchas veces una consulta puede escribirse de varias formas.

13.1 Mismo problema con subconsulta IN

SELECT nombre
FROM clientes
WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
);

13.2 Mismo problema con JOIN

SELECT DISTINCT c.nombre
FROM clientes AS c
JOIN ventas AS v ON v.id_cliente = c.id_cliente;

Ambas consultas pueden devolver los clientes que realizaron compras. La diferencia está en la forma de pensarlo:

  • Con IN: “mostrar clientes cuyo id esté en la lista de clientes con ventas”.
  • Con JOIN: “unir clientes con ventas y mostrar los que coinciden”.

13.3 Entonces, ¿cuándo conviene una subconsulta?

SituaciónPuede convenir...Por qué
Necesito comparar contra un cálculo general: promedio, máximo, mínimo.Subconsulta escalar.La consulta interna calcula un valor y la externa lo usa.
Necesito saber si un registro aparece en otra consulta.IN o EXISTS.La pregunta se piensa como pertenencia o existencia.
Necesito datos de varias tablas para mostrar columnas de ambas.JOIN.El objetivo principal es combinar información.
Necesito calcular totales por grupo.GROUP BY.El problema principal es agrupar.
Necesito filtrar grupos ya calculados.HAVING.El filtro depende de funciones de agregación.

Idea equilibrada

La subconsulta no reemplaza siempre al JOIN, ni el JOIN reemplaza siempre a la subconsulta. Son herramientas distintas. Lo importante es elegir la que exprese mejor el problema y permita escribir una consulta clara.

14. Errores comunes al usar subconsultas

14.1 Usar = con una subconsulta que devuelve varias filas

Incorrecto:

SELECT nombre
FROM clientes
WHERE id_cliente = (
    SELECT id_cliente
    FROM ventas
);

La subconsulta puede devolver varios id_cliente. Entonces = no corresponde. Una opción correcta sería:

SELECT nombre
FROM clientes
WHERE id_cliente IN (
    SELECT id_cliente
    FROM ventas
);

14.2 Olvidar el alias en una tabla derivada

Incorrecto:

SELECT *
FROM (
    SELECT id_cliente, COUNT(*) AS cantidad
    FROM ventas
    GROUP BY id_cliente
);

Correcto:

SELECT *
FROM (
    SELECT id_cliente, COUNT(*) AS cantidad
    FROM ventas
    GROUP BY id_cliente
) AS resumen;

14.3 Confundir WHERE y HAVING

WHERE filtra filas antes de agrupar. HAVING filtra grupos después de agrupar.

Incorrecto:

SELECT id_cliente, COUNT(*) AS cantidad_ventas
FROM ventas
WHERE COUNT(*) > 1
GROUP BY id_cliente;

Correcto:

SELECT id_cliente, COUNT(*) AS cantidad_ventas
FROM ventas
GROUP BY id_cliente
HAVING COUNT(*) > 1;

14.4 Escribir subconsultas innecesariamente complejas

A veces una subconsulta se puede reemplazar por un JOIN más simple o por un GROUP BY. No se trata de usar subconsultas siempre, sino de usarlas cuando ayudan.

14.5 No probar la subconsulta por separado

Una buena práctica es ejecutar primero la consulta interna para ver qué devuelve. Luego se integra dentro de la consulta externa.

Método recomendado para resolver
  1. Leer el enunciado y detectar qué se pide mostrar.
  2. Preguntarse si hay un dato intermedio necesario.
  3. Escribir primero la subconsulta sola.
  4. Verificar si devuelve un valor, una lista o una tabla.
  5. Elegir el operador correcto.
  6. Integrarla en la consulta externa.

16. Cierre conceptual

Una subconsulta no es magia ni una estructura completamente distinta: es una consulta común ubicada dentro de otra consulta. La dificultad aparece cuando debemos decidir qué devuelve esa consulta interna y cómo usar ese resultado.

Resumen final
  • Si la subconsulta devuelve un solo valor, puedo compararla con operadores como =, > o <.
  • Si devuelve una lista, puedo usar IN, ANY, SOME o ALL.
  • Si solo me importa saber si hay filas relacionadas, conviene pensar en EXISTS o NOT EXISTS.
  • Si la subconsulta depende de la fila actual de la consulta externa, es una subconsulta correlacionada.
  • Si la subconsulta está en el FROM, funciona como tabla derivada y debe tener alias.
